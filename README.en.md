# Prompt Generator for Modular AI Projects

**Version 0.4 · Meta-prompt package · Target: DeepSeek Harness**

A generator that turns a project brief into a startable project scaffold:

- a **one-page architecture** with invariants, module layers and gates,
- a **task board** with dependencies and write scopes,
- **3–5 just-in-time task briefs** instead of 25 prompts before the first line of code,
- `AGENTS.md`, `STATUS.md` and a Git repository,
- **lint + independent critic + cold-start test** instead of self-scoring.

The generator does not build the project. It builds the files with which another agent — or a team of agents — builds it.

> **Language note:** the prompt itself is currently German. An English translation is on the roadmap; the artifacts and examples are language-configurable.

---

## Quickstart

1. Copy `generator.md` into a new chat **together with** `templates/`, `rubric.md` and `tools/` (or keep the package as a folder).
2. Fill in the input block: project, mode, profile, language, budget. For brownfield projects, keep the package in `.generator/` inside the project folder; the generator adds it to `.gitignore`.
3. Answer the interview (max. 10 questions per round).
4. Approve the architecture and the task DAG; at profile S both are approved together. Only then the generator writes files into the session workspace; without a filesystem it returns code blocks.
5. Start the first task with `tasks/M01.md`; review in a new session.
6. Generate the next 3–5 briefs only when the current stage is green.

## What the generated project contains

- **Git repository:** `main`, `.gitignore`, initial commit, one commit per task (`Mxx: <title>`).
- **Module map:** `docs/module-map.md` with UI/screens, logic, data; allowed import direction.
- **`AGENTS.md`:** commands, deviations, rules, scope/git/layer rules.
- **`ARCHITECTURE.md`:** one page of invariants, non-goals, constraints, gates, deferred items, links.
- **`STATUS.md` + `board.json`:** progress derived from the board, not hand-written.
- **`tasks/M01..`:** the next 3–5 JIT briefs with context pack, gates and output format.
- **`docs/`:** module map, data model, quality, ADRs, contracts, domain.
- **S side strand:** only with a fully separate write area and a prior contract task in `docs/contracts/` (which then becomes mandatory); both strands declare `depends_on` it.

## Files

| File | Purpose |
|---|---|
| `generator.md` | The meta-prompt: phases 0–I, rules, approvals, prompts; references `templates/`. |
| `cheatsheet.md` | Human operating manual: phases, checklists, red flags. |
| `rubric.md` | 12-point rubric, lint, critic prompt, cold-start test. |
| `dsh.md` | DeepSeek Harness mapping: subagents, agent teams, board, worktrees. |
| `templates/` | Canonical templates for architecture, module map, AGENTS, task brief, board, ADR, review. `STATUS.md` is generated by `tools/render_status.py`. |
| `examples/minimal-cli/` | Complete example: a small CLI project with 6 tasks. |
| `tools/check.py` | Validates a generated project (board, budgets, links, placeholders). |
| `tools/render_status.py` | Generates `STATUS.md` from `board.json`. |

## Design principles

1. **Architecture is a contract, not a knowledge base.** Max. 800 words; only invariants that prevent modules from diverging.
2. **One file, one purpose.** `AGENTS.md` = rules, `ARCHITECTURE.md` = invariants, `STATUS.md` = progress.
3. **JIT instead of waterfall.** Only the next 3–5 task briefs.
4. **The right number of agents.** Default S: one writer, one reviewer. M/L only if at least two tasks can run at the same time across a stage without writing the same files.
5. **Gates before opinions.** Deterministic checks first; LLM review second.
6. **One writer per path.** Scopes, worktrees, board.

## Validate the example

```bash
python3 tools/check.py examples/minimal-cli
python3 tools/render_status.py examples/minimal-cli --out STATUS.md
```
