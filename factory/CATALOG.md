# Factory catalog

> Generated by `tools/factory.py catalog --write`. The source is `factory/catalog.json`.

Every item applies when one of its platforms **and** one of its traits match the project (an empty list matches everything). `must` items are done or not applicable; `should` items may be deferred with a reason. Evidence `task` means a linked board task that is done.

## Platforms

- `web` — Website or web app in the browser
- `ios` — iPhone/iPad app
- `android` — Android app
- `desktop` — Desktop app for Windows, macOS or Linux
- `cli` — Command-line tool
- `service` — Backend service or API without its own UI

## Traits

- `brownfield` — Builds on an existing repository
- `ui` — Has a graphical user interface
- `backend` — Has its own server logic or API
- `database` — Stores structured data in a database
- `accounts` — Users sign up and log in
- `payments` — Takes money: purchases, subscriptions, invoices
- `personal_data` — Processes personal data
- `uploads` — Users upload files (images, PDFs, video)
- `realtime` — Live updates, chat or collaboration
- `notifications` — Push notifications or transactional messages
- `offline` — Must work without a network
- `i18n` — More than one language or locale
- `ai` — Calls AI models
- `analytics` — Tracks usage
- `location` — Uses maps or the device location
- `deploys` — Runs on hosted infrastructure
- `public` — Launched to the public: marketing, store or search visibility
- `eu_users` — Has users in the EU (GDPR applies in addition to Swiss law)
- `cross_platform` — One shared codebase for several platforms

Implied: `platform:web` → ui, deploys; `platform:ios` → ui; `platform:android` → ui; `platform:desktop` → ui; `platform:service` → backend, deploys; `accounts` → personal_data; `payments` → personal_data; `backend` → deploys
