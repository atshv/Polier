### Observed

- The diff touches only `core/retro.py`, `tools/retro.py` and `tests/test_retro.py` inside the scope. The other files in the commit are tool-written records (`runs/M03.json`, `reviews/evidence/M03-*`). No existing test was changed and there are no placeholders. Standard library only.
- All three gate records have result `pass` and exit 0, and their commands match `docs/gates/python.md` exactly. The logs show `# fail 0`, `Ran 209 tests … OK`, `Ran 373 tests … OK (skipped=1)`, `OK: generated pages current…`, the fixture lines and `audit: 0 error(s)`.
- The gates ran on `commit 8e53b23` with `dirty: true`, before the commit. On 878f073 I re-ran `python3 -m unittest discover -s tests`: 209 tests OK, the same count as in the log, so `test_retro.py` was part of the gate run. `test_retro.py` alone: 10 tests OK.
- `python3 tools/retro.py tests/fixtures/monorepo-mini` prints one class (stalled approval) and exits 0. `minimal-cli` prints no signal and exits 0. Running it on `.` gives the garbled long-review detail quoted in finding 2.
- Edge cases from the brief: a folder given twice, a missing folder, a bad `--since` and an unreadable record are each covered by a test.

### Inferred

- The loaders in use (`load_board(strict=False)`, `runs.load_run`, `approvals.load_all`, `evidence.gate_records`) are read-only and tolerate broken files, so a broken record cannot crash the report. `_unreadable` re-parses JSON only to name such files, which does not amount to a second parser of the record format.
- `--since` keeps undated items (factory items, open questions) and drops old pending approvals. This is consistent with "ignore records dated before this day", but it means an old stalled approval disappears under `--since`.
- The scope-pressure keyword regex will miss phrasings such as "needs file X not in the brief". With the run branch dead, the class may undercount.

### Observed

- The fix commit changes only `core/retro.py`, `tools/retro.py` and `tests/test_retro.py` inside the scope, plus tool-written records (`runs/M03.json`, `reviews/evidence/M03-*`).

### Inferred

- `_evidence` pairs `record_files` and `gate_records` with `zip`. This is correct today because both functions apply the same filters in the same sorted order, but it is a coupling: if either loader changes its filters, the pairing breaks silently. The docstring states it. Not a finding.
- Repeated gate failure now depends on `gate` events in `runs/`. Those are written only when `runs.enabled(root)` (a project with a policy), so projects without run records show no repeated failures even when their evidence has them. This matches ADR-0002's attempt wording and its stated consequence ("projects without runs/ give little"). M08 should mention it.
- Gate records with no string `task` no longer appear under busy or infra gate, because `_evidence` iterates by task ID. This is an edge case with no Polier writer.
