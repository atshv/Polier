# M05 — pl_quick tool

> Role: `backend-builder` — the same as `role` on the board.

## Goal

Both harnesses offer `pl_quick`, which forwards to `tools/quick.py new` and returns its JSON.

**Why:** the owner says "fix the crash on empty input" and the agent needs a tool for the quick track (F4, AD-5); M07 adds `pl_change` next to it.

**Satisfies:** D4

**Operating the task:** claim → the lead sets `in_progress` → run the gates → `verifying` → `review` → `done` or `rework`. Approvals and escalation: `docs/orchestration.md`.

## Scope

- `pl_quick` in `plugin/lib/tools.mjs` with the parameters `title`, `scope` (list), `accept` (list of `WHEN …, THEN …` lines, required), `satisfies`, `gates`, `role`, `project`.
- Only a lead session may create a quick task (it writes `board.json`); any other session gets a tool error that says how to switch.
- Tests in `plugin/test/plugin.test.mjs` (DSH) and `claude/test/claude.test.mjs` (Claude Code), on throwaway projects.
- `docs/tools.md` regenerated with `npm run docs`.

## Out of scope

- `pl_change` (M07); process docs (M08); changes to `core/quick.py` or `tools/quick.py` (M04 is done).

## Acceptance

A1 WHEN a lead session calls `pl_quick` on a project whose build station is closed, with an existing file in scope and one `accept` line, THEN the system SHALL create the quick task and return `ok: true`, the task ID and `next`.
A2 WHEN the request is refused by `tools/quick.py` (exit 1), THEN `pl_quick` SHALL return `ok: false`, the reasons and the `next` path, not a tool error.
A3 WHEN a worker or reviewer session calls `pl_quick`, THEN the system SHALL refuse with a tool error that names `pl_mode lead`, and SHALL write nothing.

## Specifications

- **Layer/module:** harness-neutral tools — `plugin/lib/tools.mjs`; the adapters need no change.
- **Arguments:** each list item becomes one repeated flag (`--scope`, `--accept`, `--gate`); `--json` always; `--root` from `projectRoot`.
- **After a created task:** regenerate `STATUS.md` the way the other writing tools do (`render`).
- **New files:** none. **Changed files:** `plugin/lib/tools.mjs`, the two test files, `docs/tools.md`.

## Pitfalls

- `npm run check` fails while `docs/tools.md` is stale: run `npm run docs` after the definition is final.
- The Claude Code test drives the real MCP server: the lead check needs `pl_mode lead` answered through the test client's elicitation queue (see the existing lead test).

## Edge cases

- Empty `accept` list (the tool exits 2: return a tool error with its message); a project without a line; `scope` given as a string.

## Gates

1. `npm test` → `# fail 0`, Python suites `OK`
2. `npm run check` → `OK: …`
3. `claude plugin validate . --strict` → `Validation passed`

## Limits

- **Scope:** only `plugin/lib/tools.mjs`, `plugin/test/plugin.test.mjs`, `claude/test/claude.test.mjs`, `docs/tools.md`
- **Stop:** 3 attempts; when blocked, report it
- No architecture change; no new dependency
