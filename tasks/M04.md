# M04 — Quick track rule and command

> Role: `backend-builder` — the same as `role` on the board.

## Goal

`core/quick.py` decides whether a requested change qualifies for the quick track, and `tools/quick.py new` adds one `track: quick` task with its brief to `board.json` when it does.

**Why:** small changes after the build station should cost one task (F4, `docs/adr/ADR-0004-quick-track.md`); M05 exposes it as `pl_quick`.

**Satisfies:** D4

**Operating the task:** claim → the lead sets `in_progress` → run the gates → `verifying` → `review` → `done` or `rework`. Approvals and escalation: `docs/orchestration.md`.

## Scope

- `core/quick.py`: `qualifies(root, scope, title) -> (ok, reasons)` with the entry rule of ADR-0004.
- `tools/quick.py new TITLE --scope PATH… [--gate NAME…] [--role ROLE] [--json]` as in `docs/ux-flows.md#commands`; writes the task through `core/board.py` and the brief from `templates/task-brief.md`.
- `core/board.py` and `templates/board.schema.json`: an optional task field `track` with the value `quick`.
- Tests: `core/tests/test_quick.py` (the rule), `tests/test_quick_cli.py` (the command on a copy of `tests/fixtures/minimal-cli`).

## Out of scope

- `pl_quick` (M05); process docs (M08).

## Acceptance

A1 WHEN the build station of the line is closed and the scope names existing files only, THEN the system SHALL accept the request and add one pending task with `track: quick`, the next free ID, the given gates (default: the gates of the task that last touched those files, else `tests`) and `tasks/<ID>.md`.
A2 WHEN the scope names a dependency manifest, a protected path from `policy.json`, a data model file or a must item's evidence path, THEN the system SHALL refuse with the reasons and the next path (`pl_change new`), exit 1.
A3 WHEN the build station is not closed, or a quick task is already in progress, THEN the system SHALL refuse with that reason.
A4 WHEN a quick task exists, THEN `tools/state.py` and `tools/check.py` SHALL treat it like any other task (same transitions, gates, review and handoff).
A5 WHEN `--json` is given, THEN the system SHALL print one object (`ok`, `task`, `reasons`, `next`).

## Specifications

- **Layer/module:** rules — `core/quick.py`; command — `tools/quick.py`
- **Data model files:** paths named in `docs/data-model.md` or under `migrations/`; evidence paths from `factory.json` items with level `must`.
- **New files:** `core/quick.py`, `tools/quick.py`, `core/tests/test_quick.py`, `tests/test_quick_cli.py`
- **Changed files:** `core/board.py` — accept `track`; `templates/board.schema.json` — `track: {"enum": ["quick"]}`

## Pitfalls

- The schema has `additionalProperties: false` on tasks: without the schema change every quick task fails validation.
- `minimal-cli` has no `factory.json`; the CLI test adds one with a closed build station.

## Edge cases

- Empty scope; a path outside the project; a scope that is a folder; an ID collision after a deleted task.

## Gates

1. `npm test` → `# fail 0`, Python suites `OK`
2. `npm run check` → `OK: …`
3. `fixtures` (command in `docs/gates/python.md`) → both fixtures pass

## Limits

- **Scope:** only `core/quick.py`, `tools/quick.py`, `core/board.py`, `templates/board.schema.json`, `core/tests/test_quick.py`, `tests/test_quick_cli.py`
- **Stop:** 3 attempts; when blocked, report it
- No architecture change; standard library only
