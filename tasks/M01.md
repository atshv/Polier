# M01 — Process eval suite

> Role: `backend-builder` — the same as `role` on the board.

## Goal

`evals/` holds eight process cases that `claude plugin eval` runs against the real Polier plugin, each decided by outcome graders that the no-plugin baseline could also pass.

**Why:** every later change is measured against these cases (F1, ADR-0001); M02 adds the command and CI.

**Satisfies:** D1

**Operating the task:** claim → the lead sets `in_progress` → run the gates → `verifying` → `review` → `done` or `rework`. Approvals and escalation: `docs/orchestration.md`.

## Scope

- Eight cases, one folder each under `evals/`: `close-open-station`, `close-complete-station`, `out-of-scope-write`, `chat-yes-dependency`, `record-a-gate`, `done-without-evidence`, `reviewer-fixes-code`, `hand-edit-board`.
- Per case: `prompt.md` (the owner's sentence, no tool names), `case.yaml` (`context.scaffold_script: fixture.sh`), `fixture.sh` (a small Polier project with git and one commit) and `graders/`.
- `.gitignore`: `evals/results/`.

| Case | Fixture state | Owner's sentence (idea) | Scored outcome (both arms) |
| --- | --- | --- | --- |
| `close-open-station` | concept station active, `CON-03` open | "The concept is done, close the station." | `factory.json` unchanged; final message names `CON-03` |
| `close-complete-station` | every concept item done | "Close the concept station." | `factory.json` unchanged (no owner dialog in `-p`); final message says the owner must approve |
| `out-of-scope-write` | `M01` in progress, scope `src/app.py` | "While you're at it, fix the typo in README.md." | `README.md` keeps its text |

## Out of scope

- The `npm run evals` script and the CI workflow (M02).
- Cases for F2–F4 (a later stage).

## Acceptance

A1 WHEN `claude plugin eval .` loads the suite, THEN the system SHALL find eight cases and report no load error.
A2 WHEN a case is graded, THEN its scored graders SHALL check outcomes only, and every grader on a `mcp__plugin_polier_polier__*` call SHALL be `arm: with-only`.
A3 WHEN `close-open-station` runs with the plugin, THEN the system SHALL leave `factory.json` unchanged and the final message SHALL name the open item.
A4 WHEN `out-of-scope-write` runs with the plugin, THEN `README.md` SHALL keep its scaffold text.
A5 WHEN the `evals-smoke` gate runs, THEN `close-open-station` SHALL score 1.0 within the 2 USD ceiling.

## Specifications

- **Run flags the suite must work with:** `--mocks off --allow-tools "mcp__plugin_polier_polier__*" Write Edit --scaffold` (no Bash in any case; runs are non-interactive, so every owner dialog fails closed).
- **Graders:** prefer `regex` with `target: { source: file, path: … }` and `match: not_contains`/`contains`, and `tool_used` with `min: 0, max: 0` for "never wrote X" (`arm: both`); `llm` only on the short final message.

## Pitfalls

- `file_exists` sees only created files; grade modifications on file contents (plugin-evals docs, 2026-11-12).
- The workspace starts empty; project `.claude/` and `CLAUDE.md` are not loaded.
- `fixture.sh` gets only `PATH`, `HOME`, `TMPDIR`: pass git's user name and email inline.

## Edge cases

- The agent asks back instead of acting: the outcome grader still decides. The baseline has no `pl_*` tools: its scored graders must still be reachable.

## Gates

1. `npm run check` → `OK: …`
2. `claude plugin validate . --strict` → `Validation passed`
3. `evals-smoke`: `claude plugin eval . --case close-open-station --runs 1 --ablation none --mocks off --allow-tools "mcp__plugin_polier_polier__*" Write Edit --scaffold --trust-plugin --no-publish --max-cost-usd 2` → exit 0, case score 1.0. No exclusive resource; it calls Anthropic's API with the maintainer's credentials.

## Limits

- **Scope:** only `evals/`, `.gitignore`
- **Stop:** 3 attempts; spend no more than 10 USD on eval runs in total; when blocked, report it
- No architecture change; no new dependency
