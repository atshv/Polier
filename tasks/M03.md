# M03 — Retro over project records

> Role: `backend-builder` — the same as `role` on the board.

## Goal

`tools/retro.py FOLDER…` reads the Polier records of the given project folders, never writes into them, and reports error classes with count, an example record and the Polier file each class points at.

**Why:** Polier changes only for named classes of errors (F2, `docs/adr/ADR-0002-retro-read-only.md`); M08 documents the retro in the process.

**Satisfies:** D2

**Operating the task:** claim → the lead sets `in_progress` → run the gates → `verifying` → `review` → `done` or `rework`. Approvals and escalation: `docs/orchestration.md`.

## Scope

- `core/retro.py`: one function per error class of ADR-0002 (repeated gate failure, long review, scope pressure, deferred or n/a items, stalled approval, busy or infra gate), each returning `{class, count, examples, points_at}`; a `report(folders)` that combines them and lists skipped folders with a reason.
- `tools/retro.py`: the command of `docs/ux-flows.md#commands` (`--json`, `--write PATH`, `--since`), Markdown by default.
- `tests/test_retro.py` on copies of `tests/fixtures/monorepo-mini` and `minimal-cli`.

## Out of scope

- Any change to the records' format or to other tools.
- An LLM summary (later, if at all).

## Acceptance

A1 WHEN `tools/retro.py tests/fixtures/monorepo-mini` runs, THEN the system SHALL print every class that has a signal with its count, one example record path and the Polier file it points at.
A2 WHEN a folder has no `board.json`, `factory.json`, `runs/` or `reviews/`, THEN the system SHALL skip it with the reason and exit 1 if no folder had records.
A3 WHEN the retro has run, THEN the system SHALL have changed no file in any given folder (compare a snapshot of paths and mtimes).
A4 WHEN `--write PATH` is given, THEN the system SHALL write the report only to `PATH`, and refuse a `PATH` inside a given folder.
A5 WHEN `--json` is given, THEN the system SHALL print one object with `classes[]` and `skipped[]` and nothing else on stdout.

## Specifications

- **Layer/module:** rules — `core/retro.py`; command — `tools/retro.py`
- **Reuse:** the existing loaders; no second parser for runs, reviews or approvals.
- **New files:** `core/retro.py`, `tools/retro.py`, `tests/test_retro.py`
- **Reference:** `tools/audit.py` (a read-only report over the same records)

## Pitfalls

- Fixture records are committed test data: tests copy the fixture to a temp folder before running, so A3 checks the copy.
- `reviews/evidence/*.json` results include `busy`, `infra` and `timeout`; they are not failures (`prompt/generator.md`, Words).

## Edge cases

- A folder given twice; a folder that does not exist (usage error, exit 2); an unreadable record (skip it, name it in `skipped`).
- `--since` with a bad date (exit 2).
