# Polier 1.1 — design contract (work in progress)

Polier 1.1 turns the planning tool into an orchestration control plane for the
project it planned. The board stays the **plan state**; three new stores carry
what the plan alone cannot:

- `policy.json` — **rules as code**: limits, protected paths, approvals, denied
  commands. Versioned in git, checked mechanically.
- `runs/<ID>.json` — **execution state**: attempts, gate/review/state events,
  last result. One file per task, committed, the audit trail.
- `reviews/approvals/AP-NNN.json` — **human-in-the-loop records**.

Every state change of a task goes through `tools/state.py`, which enforces
deterministic checkpoints (gates before review, review before done, attempts
before another try, approval before high-risk actions). `tools/dispatch.py`
turns the board into an execution plan (waves, conflicts, blocked tasks);
`tools/audit.py` produces the compliance view for done tasks.

Vocabulary: **attempt** (one run of a task), **round** (one review round),
**checkpoint** (a state transition with preconditions), **approval** (granted
or pending record), **dispatch plan** (waves + blocked + conflicts), **policy**
(rules file), **run record** (execution log of one task). No external brand
names anywhere in shipped text.

Compatibility: a project without `policy.json` keeps working exactly as in
1.0 (`enabled: false`: no new checks, no new errors, warnings only).

## 1. Formats

### 1.1 `policy.json` (project root)

```json
{
  "version": 1,
  "limits": {
    "max_attempts_per_task": 3,
    "max_in_progress": 2,
    "max_review_rounds": 3
  },
  "scope": {
    "protected_paths": [".env", ".env.*", "secrets/**", "**/*.pem", "**/*.key", "**/id_rsa*"]
  },
  "dependencies": {
    "approval": true,
    "manifests": ["package.json", "pyproject.toml", "Cargo.toml", "go.mod", "Package.swift", "requirements.txt"]
  },
  "approvals": {
    "actions": ["new_dependency", "scope_change", "merge_to_base", "release", "reopen_done", "protected_path"],
    "approver": "owner"
  },
  "commands": {
    "deny": ["git push*", "npm publish*", "pnpm publish*", "yarn publish*", "docker push*", "gh release*", "kubectl apply*", "kubectl delete*", "terraform apply*", "rm -rf /*"],
    "lead_only": ["*tools/state.py set*", "*tools/approve.py grant*", "*tools/approve.py deny*", "*tools/worktree.py finish*"],
    "warn": ["*kill*", "*pkill*", "killall*"]
  },
  "checks": {
    "review_before_done": true,
    "handoff_before_done": true,
    "run_record": true,
    "disjoint_scopes": true
  }
}
```

Rules: `version` must be 1; unknown keys are errors; missing keys take the
defaults above; lists are lists of non-empty strings; limits are ints
(attempts 1–10, in_progress 1–64, rounds 1–20). An absent `policy.json` means
`{"enabled": false}` — the defaults above are the template, not a silent
enforcement for old projects.

### 1.2 `runs/<ID>.json`

```json
{
  "task": "M03",
  "state": "running",
  "attempt": 2,
  "attempts": [
    {"n": 1, "started": "2026-10-28T10:00:00+00:00", "ended": "2026-10-28T10:20:00+00:00",
     "result": "fail", "note": "review round 1: two blockers"},
    {"n": 2, "started": "2026-10-28T10:30:00+00:00", "ended": null, "result": null, "note": null}
  ],
  "events": [
    {"at": "2026-10-28T10:00:00+00:00", "kind": "start", "data": {"actor": "lead"}},
    {"at": "2026-10-28T10:12:00+00:00", "kind": "gate",
     "data": {"gate": "tests", "result": "pass", "record": "reviews/evidence/M03-tests-...json"}}
  ],
  "updated": "2026-10-28T10:30:00+00:00"
}
```

`state`: `idle | running | done | failed | blocked`. `attempts` grows to the
limit; `result`: `pass | fail | cancelled`. `events` is append-only, last 500
kept. Event kinds: `start`, `gate`, `review`, `state`, `approval`, `note`,
`escalate`. Written atomically under a `<file>.lock` (O_CREAT|O_EXCL, stale
after 60 s); reader tolerates a missing or broken file.

### 1.3 `reviews/approvals/AP-NNN.json`

```json
{
  "id": "AP-001",
  "action": "new_dependency",
  "task": "M09",
  "status": "pending",
  "requested_by": "worker",
  "requested_at": "2026-10-28T11:00:00+00:00",
  "approved_by": null,
  "approved_at": null,
  "note": "adds httpx 0.27 for the API client"
}
```

`status`: `pending | granted | denied`. One file per approval, ID is
`AP-` + 3+ digits, allocated under a lock and reserved with `O_CREAT|O_EXCL`.
Grant/deny set `approved_by`, `approved_at`, `note` (append to note with
`" | "`), and append a `runs/<task>.json` `approval` event when the task is
known. A granted record is the approval; there is no expiry.

## 2. Core modules (Python 3.9+, stdlib only)

### `core/policy.py`

```python
POLICY = "policy.json"
DEFAULTS: dict                     # the object above, without "version"/"approvals.aprover"? no: full default
ACTIONS = ("new_dependency", "scope_change", "merge_to_base", "release", "reopen_done", "protected_path", "state_override")
def load_policy(root, strict=False) -> dict
    # {"enabled": False} when absent (strict -> PolierError); else DEFAULTS deep-merged
def policy_errors(policy) -> list[str]
def enabled(policy) -> bool
def limits(policy) -> dict                    # ints with defaults
def action_required(policy, action) -> bool   # action in approvals.actions
def approver(policy) -> str
def path_matches(pattern, rel) -> bool        # '**' segment aware, case-insensitive on macOS/Windows
def protected_match(policy, rel) -> str|None  # first matching protected pattern
def manifest_match(policy, rel) -> str|None
def command_denial(policy, command, role="worker") -> dict|None
    # {"rule": "deny"|"lead_only", "pattern": str, "command": str, "reason": str}
def glob_match(pattern, text) -> bool         # fnmatch-style, case-insensitive for commands on every OS
```

Path matching: patterns are `/`-separated; `**` matches zero or more segments,
`*`/`?` match inside one segment (fnmatch per segment); a pattern without `/`
matches the basename at any depth (`.env` matches `.env` and `sub/.env`).
Command matching: split the command into shell segments (`core/shell.py`
helpers), strip quotes, heredocs, assignments and wrappers (`sudo`, `env`,
`nohup`, ...), join the tokens with single spaces, then `glob_match` the
pattern against that segment text. Text inside quotes or heredocs never counts.
`lead_only` only denies roles `worker` and `reviewer`; `deny` denies every role.

### `core/state.py`

```python
TRANSITIONS = {"pending": {"claimed","in_progress","blocked","failed"}, ...}
def check_transition(root, board, task, new_status, *, actor="lead", note=None, force=False) -> dict
    # {"ok": bool, "errors": [str], "warnings": [str], "requires": [str], "actions": [dict]}
def set_status(root, task_id, new_status, *, actor="lead", note=None, force=False) -> dict
    # raises TransitionBlocked (PolierError) with .errors/.actions when a checkpoint fails
def status_of(root, task_id) -> dict      # board status against run record, gates, review, approvals, attempts
```

Transition table:

| from | to |
|---|---|
| pending | claimed, in_progress, blocked, failed |
| claimed | pending, in_progress, blocked, failed |
| in_progress | verifying, blocked, failed |
| verifying | review, rework, blocked, failed |
| review | done, rework, blocked, failed |
| rework | in_progress, blocked, failed |
| blocked | pending, in_progress, failed |
| failed | pending, in_progress |
| done | rework (reopen; approval `reopen_done`) |

Preconditions (hard errors unless noted):

- any target: task exists; transition allowed; stage not stopped; target not
  `done` without leaving it (see reopen). Changing a `done` task needs a
  granted `reopen_done` approval.
- `in_progress`: open attempts used < `max_attempts_per_task` (otherwise
  blocked with the escalation command hint); `in_progress` count excludes
  this task and is < `max_in_progress`; stage not behind incomplete stage
  dependencies (same rule as `check.py`).
- `verifying`: a run record attempt is open (skeleton allowed: it is started
  by the transition to `in_progress`).
- `review`: every gate in `task.gates` has a passing record for this task in
  `reviews/evidence/` (result not infra/busy/timeout, exit_code 0).
- `done`: all of the above; if `checks.review_before_done`: `reviews/<ID>.md`
  contains `verdict: pass`; if `checks.handoff_before_done` and other tasks
  depend on it: `handoff` with 1–3 lines; if `checks.run_record`: run record
  exists; if any `scope_write` entry matches a dependency manifest and
  `dependencies.approval`: granted `new_dependency` approval for this task.
- `rework`: `note` required; round would exceed `max_review_rounds` → error;
  increments `task.round` by 1 and closes the attempt as `fail`.
- `blocked`: `note` required (reason and what is needed); closes the attempt
  as `cancelled` and appends an `escalate` event.
- `failed`: `note` required; closes the attempt as `fail`.
- `force=True`: requires a granted `state_override` approval; every forced
  change appends a warning event.

Side effects of `set_status`: atomic board write (temp file + `os.replace`
under `board.json.lock`), `runs` events/attempts as above, round increment on
`rework`, no other files.

### `core/dispatch.py`

```python
def plan(root, board=None, policy=None) -> dict
```

Result:

```json
{
  "project": "x", "profile": "M",
  "limits": {"max_attempts_per_task": 3, "max_in_progress": 2},
  "running": [{"id": "M03", "title": "...", "status": "in_progress", "attempt": 2,
               "max_attempts": 3, "claim": {"harness": "dsh", "session": "..."} | null}],
  "waves": [[{"id": "M04", "title": "...", "brief": "tasks/M04.md", "parallel_group": null}]],
  "blocked": [{"id": "M07", "reason": "...", "action": "python3 tools/state.py set M07 blocked --note ..."}],
  "conflicts": [{"a": "M04", "b": "M05", "paths": ["src/db/"]}],
  "approvals_pending": [{"id": "AP-002", "action": "new_dependency", "task": "M09"}],
  "next": ["M04"]
}
```

Rules: candidates are `ready_tasks()`; a task with `attempts >= max` is
blocked (escalate action); a task whose brief is missing is blocked
(`tasks/<ID>.md`); a task claimed by a live session of another task is
`running` for that ID, not a wave member. Concurrency contract: tasks with
the same non-empty `parallel_group`, same stage and pairwise disjoint
`scope_write` may share a wave; a task without a group is a wave of its own;
groups are packed in board order up to `max_in_progress` per wave. Overlapping
scopes inside a group go to `conflicts` and only the first task stays in the
wave. `checks.disjoint_scopes: false` turns the exclusion into a warning (the
task still moves to `conflicts` but stays in the wave).

Blocked reasons for non-ready tasks: `stage stopped by the owner`,
`stage waits for <id>`, `waits for <task>`, `attempts 3/3 used — escalate`,
`brief tasks/M07.md is missing`, `claimed by another session (dsh)`.

### `core/audit.py`

```python
def audit_task(root, board, task, policy) -> dict
def audit(root, board, policy=None) -> dict   # {"tasks": [...], "errors": [...], "warnings": [...]}
```

Per task: board status, attempts used/limit, gate list/passed/missing, review
file+verdict, approvals per action, handoff present, run record present,
findings. For a `done` task every enabled check is an **error**; for other
statuses findings are warnings. Exit code of the CLI is 1 iff any error.

## 3. CLI tools

All tools follow the existing style: `argparse`, positional project folder
(default `.`), `--json` where the plugin needs it, exit 0/1/2
(0 ok, 1 finding/refusal, 2 usage/environment error), no external packages.

### `tools/state.py`

```
python3 tools/state.py show [ID] [--json] [--root DIR]
python3 tools/state.py set ID STATUS [--actor lead] [--note TEXT] [--force] [--root DIR]
python3 tools/state.py check ID STATUS [--json]   # evaluate, never write
```

`set` prints the transition, side effects (attempt N/M, round R), warnings and
the next checkpoint. Refusal prints each blocker plus an `action` hint (e.g.
`python3 tools/state.py set M03 blocked --note "..."`, `tools/approve.py
request --action new_dependency --task M03`).

### `tools/approve.py`

```
python3 tools/approve.py request --action ACTION [--task ID] [--by worker] [--note TEXT]
python3 tools/approve.py grant AP-001 [--by owner] [--note TEXT]
python3 tools/approve.py deny AP-001 [--by owner] [--note TEXT]
python3 tools/approve.py list [--json] [--status pending|granted|denied]
python3 tools/approve.py check --action ACTION [--task ID] [--json]
```

`check` exits 0 only when a granted record matches action+task (task
`null` matches any).

### `tools/dispatch.py`

```
python3 tools/dispatch.py [--root DIR] [--json] [--limit N]
```

Text form: limits, running, `Next wave`, later waves, blocked with actions,
conflicts, pending approvals. `--json` prints `core.dispatch.plan()`.

### `tools/audit.py`

```
python3 tools/audit.py [--root DIR] [--json] [--task ID]
```

Text form: one block per task with status, attempts, gates, review, handoff,
approvals; then `errors` and `warnings`. Exit 1 when errors.

## 4. Integration points

- `tools/gate.py`: after writing a record, when `core.policy.enabled(root)`,
  call `core.runs.record_gate(root, task, name, result, rel_record)`; a
  failure there is swallowed (never affects the gate result).
- `tools/check.py`: load policy (warn when absent); validate policy; run
  `core.audit.audit` (errors/warnings); validate approvals with
  `core.approvals.errors`; validate `runs/*.json` (parse, task id matches
  file, attempts ints, state known); flag two `in_progress` tasks with
  overlapping scopes; flag `attempts > limit`; run `core.dispatch.plan` and
  report `conflicts` as errors, blocked as warnings; require `policy.json`,
  `docs/orchestration.md`, `runs/` in AGENTS.md/README when policy is enabled
  (warnings). STATUS freshness keeps working (render + strip claims).
- `tools/render_status.py`: new `## Orchestration` section when a policy or
  runs exist: limits; `Next wave`; running with attempt N/M; blocked/escalated
  with reason; pending approvals. Keep the section ≤ 10 lines (STATUS budget).
- `core/board.py`: `stage_report()` gains `tasks_open` (ids not `done`) and a
  stage is `complete` only when `tasks_open` is empty; `render_status.py`
  shows `tasks open: …`. `ready_tasks()` behaviour unchanged.
- `core/scope.py`: `BOARD_FILES` gains `runs`; a reviewer may not write
  `reviews/approvals` (code `approvals`); new codes are added to
  `core/tests/write_cases.json` and the JS mirror.
- DSH plugin (`adapters/dsh/lib/policy.mjs`, `index.mjs`): mirror
  `protected_match`, `manifest_match`, `command_denial` and
  `has_grant` (reads `reviews/approvals/*.json`). Guard order: role/scope
  rules, then policy (protected path, dependency manifest without approval,
  denied command, lead-only command). Lead bypasses path/dependency rules,
  nobody bypasses `deny` commands. New tools `pl_next` (dispatch JSON) and
  `pl_state` (`show`/`set` through `tools/state.py`); `/pl next` and
  `/pl policy` in the command help.
- Claude Code hook (`adapters/claude-code/hook.py`): same policy checks for
  `Write`/`Edit`/`MultiEdit`/`NotebookEdit` paths and `Bash` commands, via
  `core.policy`; denial JSON as the existing hook format. `POLIER_ROLE` is
  the role for `lead_only`.
- `core/tests/policy_cases.json`: shared table for Python and JS:
  `{"path_cases": [{"name", "rel", "pattern", "ok"}], "command_cases":
  [{"name", "command", "pattern", "role", "denial": "deny"|"lead_only"|null}],
  "policy": {...}}`.

## 5. Templates and process

- `templates/policy.json` — the default object of §1.1 (profile values are set
  by the generator; a board override is not needed).
- `templates/orchestration.md` — one page for generated projects: the task
  loop, the stage loop, the checkpoints, approvals, escalation, where the
  files are. Generated as `docs/orchestration.md`.
- `templates/AGENTS.template.md` gains the rules: state changes only with
  `tools/state.py`; gates only with `tools/gate.py`; approvals only with
  `tools/approve.py`; never edit `runs/`, `reviews/approvals` or `board.json`
  by hand; run `tools/dispatch.py` before starting a task; `runs/` and
  `policy.json` belong to the project and are committed.
- `prompt/generator.md`: phase 0.3 (limits per profile), D (write
  `policy.json`, limits, manifest list), E (loop and approvals), G (scaffold
  `policy.json`, `docs/orchestration.md`, `runs/`, `reviews/approvals/`),
  H (`audit.py` + `dispatch.py` green), I (worker/orchestrate/review/fix/
  escalation prompts use `state.py`, `dispatch.py`, `approve.py`).
- `prompt/orchestration.md` (new): the shipped model — plan/execution/liveness
  state, task loop, stage loop, checkpoints, approvals, escalation, patterns
  mapping (sequential via `depends_on`, concurrent via `parallel_group`,
  handoff via `handoff`, stage stop via `owner_decision`), what is not
  covered.
- `prompt/rubric.md`, `prompt/dsh.md`, `SKILL.md`, `guide/cheatsheet.md`,
  `README.md`, `CHANGELOG.md`, `VERSION`, `package.json`: 1.1.0.
