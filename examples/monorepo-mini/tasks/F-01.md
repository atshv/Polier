# F-01 — Workspace scaffold and package map

## Goal

The four workspace folders, their package files, the root documents and the layout gate exist and agree with `packages[]` on the board.

**Why:** Every later task writes inside this skeleton. The package map and the root documents are the context every worker loads, so a wrong path here costs every task.

**Satisfies:** D1

## Scope

- root documents: `ARCHITECTURE.md`, `AGENTS.md`, `README.md`, `.gitignore`, `.env.example`
- the documentation set under `docs/`, including the package map, quality, versions, environments, design rules, gate catalogue and ADRs
- four package folders with their build manifest and `ARCHITECTURE.md`: `packages/engine`, `packages/ui-kit`, `services/sync`, `apps/web`
- `tools/layout_check.py`, the scaffold gate that ties the board to the folders

## Out of scope

- any feature code inside a package — the later stage tasks own that (ENG-01, API-01, WEB-01, WEB-02)
- the state contract and its fixtures (F-02)
- CI configuration and the release tag (REL-01)
- a database, authentication, analytics (not in 1.0)

## Acceptance

A1 WHEN the package map is compared with the working tree, THEN the system SHALL find one folder per `packages[].path`, each with an `ARCHITECTURE.md` within the 400-word budget, and `python3 tools/layout_check.py` SHALL exit 0.

A2 WHEN a package folder or its `ARCHITECTURE.md` is missing, THEN the layout gate SHALL exit 1 and name the package path in its output.

A3 WHEN a new worker reads only `ARCHITECTURE.md`, `AGENTS.md`, `STATUS.md` and `docs/module-map.md`, THEN the system SHALL give the package paths, the dependency direction and the gate names without a further root document.

## Context pack

**Read exactly:**

- `ARCHITECTURE.md` (sections 3–6)
- `docs/quality.md` (definition of done D1–D5)
- `docs/monorepo-layout.md` (root files, package files, budgets)
- `docs/module-map.md` (package table)
- `packages/engine/ARCHITECTURE.md` (shape of a package file)
- `tools/layout_check.py` (what the gate checks)

**Do not read:** other task briefs, the contract fixtures, package sources.

**Budget:** ≤ 15,000 tokens input.

## Specifications

- **Package map:** four entries on the board — `packages/engine` (package), `packages/ui-kit` (package), `services/sync` (service), `apps/web` (app). Each folder gets an `ARCHITECTURE.md` (max. 400 words) and a build manifest: `CMakeLists.txt` for the engine, `package.json` for the other three.
- **Root architecture:** system shape, package kinds, dependency direction and the invariants AD-1 … AD-6; max. 800 words, no folder tree.
- **Root `AGENTS.md`:** commands per package, runtime rules (slots, exclusive gates, no kill), git rules, profile L rules; max. 400 words.
- **`docs/`:** module map, monorepo layout, quality, versions, environments, releasing, design rules, ADRs, gate catalogue.
- **`tools/layout_check.py`:** standard library only; reads `board.json`, checks folders, package `ARCHITECTURE.md` budgets, `may_import` entries, the module map and the contract files; exit 0 clean, 1 findings, 2 configuration error.
- **`.gitignore`:** `node_modules/`, `.next/`, `build/`, `build-wasm/`, `__pycache__/`, `.polier-slot`, `.generator/`, `.env*`, editor and OS files.
- **Changed files:** the paths in the scope line.
- **Reference:** `docs/monorepo-layout.md` for the root-file and package-file split.

## Pitfalls

- A folder that exists but is not on the board is invisible to every gate; add the package to `packages[]` or move the files.
- The board package path and the folder path must match exactly — trailing slashes are normalised, case is not.
- `.generator/` is the Polier copy: gitignore it, never edit it inside the project.
- Root documents are limited by the profile L budget; details belong in `docs/`, not in `ARCHITECTURE.md`.

## Edge cases

- A package task that creates its folder later: the folder must already be declared and the plan must name the creating task.
- An empty `docs/` folder is not allowed; every document in it is linked from `README.md` or `ARCHITECTURE.md`.
- `.gitignore` must not ignore `reviews/evidence/` — gate records are committed evidence.

## Gates

1. `python3 tools/layout_check.py` → exit 0, four packages and one contract reported.
2. `wc -w ARCHITECTURE.md AGENTS.md` → within 800 and 400 words for profile L.
3. `grep -c "packages/engine\|packages/ui-kit\|services/sync\|apps/web" docs/module-map.md` → each path found.

A gate passes when command, exit code and expected output match; the output is the evidence. If a gate fails: read the cause, fix the file, rerun the gate.

## Limits

- **Scope:** only `ARCHITECTURE.md`, `AGENTS.md`, `README.md`, `.gitignore`, `.env.example`, `docs/`, `packages/`, `services/`, `apps/`, `tools/layout_check.py` — nothing under the contracts folder
- **Stop:** max. 2 rework rounds; when blocked, `status: blocked` plus reason
- No new dependencies; no architecture change without an ADR
