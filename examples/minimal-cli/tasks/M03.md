# M03 — Add, List und Search

## Ziel

`bm add`, `bm list` und `bm search` funktionieren auf einer frischen Datenbank.

**Warum:** Das ist der MVP-Nutzen. M04 (Tags) und M06 (E2E) bauen auf diesen Befehlen und dem Service auf.

## Umfang

- `bm add <url> [--title <t>]`: URL kanonisieren, speichern, ID ausgeben
- `bm list`: alle Einträge, neueste zuerst
- `bm search <text>`: URL und Titel durchsuchen, Groß-/Kleinschreibung egal
- Fehlerbehandlung für ungültige URL, Duplikat und DB-Fehler
- Tests für Service und CLI

## Nicht Teil davon

- Tags (M04)
- Export/Import (M05)
- `--limit`, Pagination, Sortieroptionen (nach MVP)
- Volltext-Index (nicht V1)

## Akzeptanz

A1 WENN `bm add https://example.com --title "Beispiel"` ausgeführt wird, DANN SOLL das System die URL kanonisieren, speichern und die neue ID ausgeben; Exit 0.

A2 WENN dieselbe kanonische URL erneut gespeichert wird (auch mit anderer Schreibweise, z. B. Großbuchstaben im Host oder Trailing Slash), DANN SOLL das System `URL existiert bereits` ausgeben, nichts speichern und Exit 2 liefern.

A3 WENN `bm list` ausgeführt wird, DANN SOLL das System alle Einträge nach `created_at` absteigend ausgeben, je Zeile ID, URL und Titel; Exit 0.

A4 WENN `bm search <text>` ausgeführt wird, DANN SOLL das System alle Einträge ausgeben, deren URL oder Titel den Text als Substring enthält, unabhängig von Groß-/Kleinschreibung; bei keinem Treffer `Keine Treffer` ausgeben und Exit 0.

A5 WENN die URL ungültig ist (kein Schema, kein Host, leer), DANN SOLL das System `Ungültige URL` ausgeben, nichts speichern und Exit 2 liefern.

A6 WENN die Datenbank nicht geöffnet werden kann, DANN SOLL das System `Datenbank nicht erreichbar` ausgeben und Exit 1 liefern; die CLI darf keinen Traceback zeigen.

## Vorgaben

- **Schicht/Modul:** Logik (`bm/service.py`) plus CLI-Verdrahtung (`bm/cli.py`); Store bleibt unangetastet.
- **Service-API (M03):**
  - `add_bookmark(url: str, title: str | None) -> int`
  - `list_bookmarks() -> list[Bookmark]`
  - `search_bookmarks(text: str) -> list[Bookmark]`
  - `Bookmark` als Dataclass mit `id`, `url`, `title`, `created_at`
- **URL-Kanonisierung:** `urllib.parse`; Schema und Host lowercase; Standardport entfernen; Trailing Slash entfernen (außer bei Root `/`); Query und Fragment bleiben erhalten.
- **Duplikat:** über `UNIQUE(url)` im Schema und `sqlite3.IntegrityError` abfangen; keine Vorab-Abfrage nötig.
- **CLI:** Typer; Ausgabe Deutsch; Exit-Codes wie in der Akzeptanz. Keine Fachlogik in `cli.py`; nur Argumente, Service-Aufruf, Ausgabe.
- **Titel:** optional; ohne Titel leerer String, nicht `None` in der DB.
- **Zeitstempel:** UTC ISO-8601, gesetzt im Service oder Repository (nicht in der CLI).
- **Dateien neu:** `bm/service.py`, `tests/test_service.py`
- **Dateien ändern:** `bm/cli.py`, `tests/test_cli.py`
- **Vorbild:** `tests/test_store.py` und `bm/store/repository.py` aus M02.

## Stolperfallen

- `sqlite3` prüft die `UNIQUE`-Constraint bereits beim `execute` der INSERT-Anweisung und wirft dort `IntegrityError`; `commit` kann bei deferred Constraints ebenfalls werfen. Beide Pfade behandeln (verifiziert mit Python 3.12; Doku: https://docs.python.org/3/library/sqlite3.html#sqlite3.IntegrityError).
- Typer: Exit-Codes über `typer.Exit(code=...)`, nicht `sys.exit` mitten in der Funktion.
- URL mit Leerzeichen/Benutzername/Passwort: nicht raten, als ungültig behandeln (V1).
- `datetime.utcnow()` ist deprecated; `datetime.now(timezone.utc)` verwenden.

## Sonderfälle

- URL mit Trailing Slash und Großbuchstaben im Host → dasselbe Duplikat.
- `bm search ""` → `Keine Treffer`, Exit 0.
- Titel mit Umlauten → UTF-8 korrekt ausgeben.
- DB-Datei im falschen Format → als DB-Fehler behandeln, keine Rohdaten überschreiben.
- Sehr lange URL (> 2000 Zeichen) → `Ungültige URL`, Exit 2.
